  1. 2026-11-13

    Inspected the site and planned the pages

    What I tried, and why

    Read the repository first. The site is a single hand-written index.html with inline CSS and JavaScript, served by GitHub Pages straight from the main branch (no build step, no workflow files). So each new page became its own folder with an index.html: /python-playground/ and /python-cheat-sheet/, plus shared styles in /assets/learn.css.

    What broke

    The build sandbox's network refused the CDNs the playground needs: requests to cdn.jsdelivr.net and esm.sh failed with "CONNECT tunnel failed, response 403". That meant Pyodide couldn't be loaded from its CDN while testing.

    How I fixed it

    Installed the same Pyodide release (0.29.5) from npm and had the test browser answer requests for the CDN URLs with those local files. The page itself still loads Pyodide from the official CDN; only the test harness swaps the source, and because the files are the same release, the test exercises the same code that ships.

  3. 2026-11-13

    Bundled the CodeMirror 6 editor into one file

    What I tried, and why

    Loading CodeMirror 6 directly from a CDN means importing many small packages that must share one copy of @codemirror/state, which CDNs don't always guarantee. Instead, bundled the editor (line numbers, history, bracket matching, Python highlighting, a dark theme) with esbuild into python-playground/vendor/codemirror.min.js, and kept the entry file and rebuild steps next to it.

    This step went smoothly.

    This was a precaution, not a reaction to an observed failure. The cost is a 377 KB file (127 KB gzipped) in the repo that has to be rebuilt by hand to upgrade.

  4. 2026-11-13

    Ran Python in a Web Worker and wrote the five lessons

    What I tried, and why

    Put Pyodide in a Web Worker (worker.js) so a beginner's infinite loop can't freeze the page: the page stops the worker after 10 seconds and starts a fresh one. Wrote the five lessons in lessons.js, each with a Python check made of assert statements whose messages become the hints. The conditionals check re-runs the user's code with other scores via run_with(score=...), so hard-coding the answer doesn't pass. Before testing, changed the loops check to look only at the last five printed lines, so learners don't have to delete the example code first.

    This step went smoothly.

  5. 2026-11-13

    First test run: lost output and a trimmed traceback

    What I tried, and why

    Ran an automated browser test through every lesson: run the starter, check a wrong answer, check a right answer, then error cases.

    What broke

    All five lessons passed and failed correctly, but print("no newline", end="") showed "(Your code ran but didn't print anything.)". Pyodide's line-batched stdout callback never delivered the final line because it had no newline, even with sys.stdout.flush() at the end of the run. Separately, SyntaxError tracebacks lost the two leading spaces on their File "main.py" line.

    How I fixed it

    Replaced the batched callback with raw write handlers (pyodide.setStdout({ write })) that decode bytes with a streaming TextDecoder, so every byte printed reaches the page whether or not it ends in a newline. For the traceback, trimmed only trailing whitespace instead of calling trim(), which had also stripped the leading indentation.

  6. 2026-11-13

    An infinite print loop swamped the page

    What I tried, and why

    Tested while True: print("spam"), expecting the 10-second timeout message.

    What broke

    The test gave up: "page.waitForFunction: Timeout 25000ms exceeded" while waiting for the timeout message. Each print() was sent to the page as its own message, so the page spent its time appending thousands of tiny updates and scrolling after each one.

    How I fixed it

    The worker now batches output and sends it every 50 ms or 4 KB, whichever comes first, and the page scrolls at most once per animation frame. Output is still capped at 50,000 characters. On the re-run the timeout fired and the output showed the truncation notice.

  10. 2026-11-13

    Committed the cheat sheet generator and corrected the loading message

    What I tried, and why

    Started the architecture page by checking every claim against the code. Two problems turned up. The cheat sheet's generator script had only existed outside the repository, so the page couldn't be regenerated from what was committed. And the playground's loading message said the first visit "downloads about 10 MB", a number that had never been measured.

    What broke

    Measuring Pyodide 0.29.5's core files (pyodide.js, pyodide.asm.js, pyodide.asm.wasm, python_stdlib.zip, pyodide-lock.json) gave 12.3 MB uncompressed, about 5.5 MB gzipped, so "about 10 MB" matched neither.

    How I fixed it

    Added the generator, its template and a README under python-cheat-sheet/source/, and confirmed it regenerates the published page byte-for-byte. Changed the loading message to "the first visit takes a few seconds while it downloads", which is true whatever the compression.

  11. 2026-11-13

    Built the interactive architecture page

    What I tried, and why

    Wrote architecture.json by reading each part of the code: 10 components and 11 connections, with code excerpts copied by line range rather than retyped, and decisions taken from code comments and READMEs. Two draft decisions (why Pyodide is pinned, why lessons use URL hashes) gave reasons the code doesn't state, so they were rewritten to describe only what the code does, with a TODO for the reasoning. The page renders the diagram as SVG from the JSON with no libraries, and a small script (architecture/tools/build.py) checks that every excerpt still matches its file and writes the static text version.

    What broke

    Testing turned up five problems. The text version's code blocks had 16 extra spaces on every line after the first: the same <pre> indentation mistake as the cheat sheet generator. The detail panel's heading reported "Select a component" after a node was opened, because the placeholder and the real heading shared the id detailTitle. While zoomed in, clicking another node failed with "element is outside of the viewport". With JavaScript turned off, the empty diagram area still showed, because CSS display rules overrode the hidden attribute. And in screenshots, edge labels were clipped by the boxes on either side (only a 46-pixel gap) and rendered at about 8 pixels.

    How I fixed it

    Stopped re-indenting generated HTML. Gave the placeholder heading its own id and pointed the panel's aria-labelledby at whichever heading is showing. Made the view pan to any node that receives keyboard focus while zoomed (mouse users can use the Connections list or Back to overview). Added a site-wide [hidden] { display: none !important; } rule. Widened the column gaps to 100 pixels, gave the diagram two-thirds of the row, enlarged the text and shortened the edge labels; an automated check then found no label overlapping a box.

  12. 2026-11-13

    Accessibility pass across the new pages

    What I tried, and why

    Looked at the new pages in screenshots and ran the axe-core accessibility checker on all of them, at desktop and phone widths.

    What broke

    Screenshots showed the header subtitle and nav pills were hard to read against the bright sky in the background photo. axe reported the cheat sheet's sideways-scrolling code blocks as "scrollable-region-focusable" (13 blocks): keyboard users couldn't scroll them. axe also marked text on the see-through panels as needing manual contrast review, since it can't measure text over a photo. On a phone, a failed Pyodide load made the playground 455 pixels wide on a 375-pixel screen, because the error message includes a long URL that couldn't wrap.

    How I fixed it

    Darkened the glass panels from 35% to 60% black and lightened the grey text. Working out the worst case (pure white behind a panel) by hand, body text now stays above the 4.5:1 contrast minimum. Gave the header text and nav pills a dark backing. Made the cheat sheet's code blocks focusable, through the generator so it survives regeneration, with a visible focus ring. Let the playground's status text wrap. After the changes, axe reported no violations on any page at desktop width. At phone width, one remained: CodeMirror's internal scroll container. That one was left as is, because keyboard users focus the editor itself and the view follows the cursor.

  14. 2026-11-13

    Civ Terminal: first playable slice

    What I tried, and why

    Started a new project at /civ-terminal/: a civilization sim played in a terminal, on a pure black page with a WebGL wireframe map. Built a vertical slice before anything else: one era (Stone Age), two structures, two dilemma cards, one tit-for-tat rival with a recurring arms-race decision, and the boot log and name prompt working end to end. The simulation is plain JavaScript with a seeded random stream, so the same seed and the same choices always give the same score, and game content lives in JSON data files. The map is raw WebGL2 with no library; settlers, huts and hearths are drawn in one instanced call.

    What broke

    Running the tests with "node --test tests/" failed outright with "error: 'test failed'" and ran nothing. Two of my own tests were wrong: both assumed no decision was waiting when the shared-store card had correctly come up at turn 4. A report showed that against a lone tit-for-tat rival, always disarming won on all six seeds tried, so a test titled as if no strategy always wins was claiming something the slice can't show. In the browser, an effect of -0.15 stability per turn displayed as "-0.1", the prompt line sat indented and detached from the output, and the map was cropped on the left with empty space above it.

    How I fixed it

    Pointed the test script at tests/*.test.js. Corrected the two tests to answer the waiting card first, and renamed the strategy test to a plain report, with a note that the claim needs the other rival strategies in play. Printed per-turn stability to two decimals. The stray indent came from line breaks in the HTML inside an element that preserves whitespace, so the input line's markup went onto one line. The camera now works out, for whatever shape the map pane is, how steeply to look down and how far to back off so the whole map fits.

    The deploy for this commit was cancelled when the next commit was pushed 43 seconds later. The next deploy carried it live.

  15. 2026-11-13

    Civ Terminal: from a terminal to a colorful pixel-art game

    What I tried, and why

    Feedback after playing the first slice: it shouldn't stay a terminal. The terminal is now only the start screen; naming the civilization opens a small old-school game screen with a blue river, trees and hills, and buttons for building. The WebGL wireframe map was replaced with a 320x200 pixel-art map on a plain 2D canvas, which is lighter. New rules from the same feedback: only campfires can be built until 15 knowledge (fires spread knowledge), cooking is discovered at 8 knowledge and speeds up learning, and expeditions go out and come back with 1 knowledge. These are data files (discoveries.json, expeditions.json), so more can be added without code.

    What broke

    The report was that building didn't take energy. Checking first: it did (energy 100 went to 90 in a test), but the terminal only answered "Built a hearth" and never showed the numbers, so it looked like nothing happened. The game screen now shows costs on the buttons, animates changes on the resource bar, and the log says what was paid. Then testing in a browser found more. The disabled-button marker was written as aria-disabled="" instead of "true", so locked buttons weren't dimmed and would have been announced as enabled; my own test noticed because it never found a "false" value. The decision card measured 1,689px tall on a 900px screen and sat at the bottom: the screen's fade-in animation left an identity transform behind, and any transform makes fixed-position children position against that element instead of the window. After a decision closed, keyboard focus landed on nothing, because the buttons are redrawn and the old one was gone. Two of my own tests were wrong (one crossed 8 knowledge during the "before cooking" case; one forgot a newborn adds energy). A bot playing well finished the Stone Age at turn 20, too quick.

    How I fixed it

    Wrote aria-disabled as "true"/"false". Changed the fade-in to opacity only, and made the card center itself without being cut off. Focus now returns to the same control by name. Fixed both tests. Moved the end of the Stone Age from 40 to 60 knowledge: the same bot now takes about 28 turns. Also shrank the map from 384x240 to 320x200 so buildings read larger, made the build buttons one per row, and capped the floating +/- numbers at three per resource. Added 20 unit tests and a browser smoke test (34 checks) to the repo. Saves from the first build are not loaded, since the state changed.
